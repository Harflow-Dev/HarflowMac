# M08-A1 — Native workflow library

Status: locally implemented and verified, 2026-11-17. This is a bounded M08
slice, not acceptance of full M08, M07 or M12.

The Workflows destination now uses a lightweight public-list lifecycle and approved list, empty,
loading and New workflow menu designs. Edit opens the exact saved name and Run opens the retained
permission-preview launcher. Blank and generated drafts retain the existing editor and draft
safeguards; generation intent belongs to one navigation UUID. No direct workflow start is added.
Runtime/epoch, mount and request fences reject stale reads and callbacks, including runtime ABA.
Read failures remain source-scoped incidents with persistent details and refresh; failed reads
never become empty results. Optional node counts come only from actual definition arrays.

Design references and lifecycle ownership are documented in [architecture](../architecture.md#native-workflow-library).
`WorkflowLibraryVMTests` covers routing, lifecycle, metadata, failures, equality and stale callbacks.
The registered `WorkflowLibraryHostedTests` uses isolated injected fixtures and owned native windows
at 1280×800 and 1000×620 in both appearances, with additional 720-point pane long-content checks.
These are pane dimensions, not whole-window dimensions with a visible sidebar. Primary owns the
serialized validation lane. Observed results follow below.

The hosted suite also exercises both actual native New workflow menu items. It opens the native
popup through an owned-window Space event and selects each native item. SwiftUI Edit/Run keyboard
activation is qualified only when macOS Full Keyboard Access permits AX focus; otherwise
`workflow-library-keyboard.txt` explicitly records the unverified reason. No keyboard preference
is changed. AX activation, native popup keyboard activation and full Edit/Run keyboard traversal
are separate evidence; full M08/M12 keyboard acceptance remains open.
