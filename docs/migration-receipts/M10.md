## Native behavior

The Statistics header keeps the period selector visible during the
read and across unavailable states. The chart and coverage use the
selected bounded retained history. An older read cannot replace the
selected period's visible results.

The Reported cost card uses the same fresh admitting ctl probe as the
page request. It requires `statistics-cost-model.v1`, a complete
single-generation walk and matching coverage on every page. The Mac
reconciles counts against the entire snapshot before applying the
selected execution cohort. Native logical children are excluded.
Incomplete reported cost shows Unavailable and verified counts.
Unqualified cost shows coverage unavailable while complete time and
usage remain usable. A reported zero displays $0.00.

The approved partial-accounting drawing phrases coverage in harnesses.
The public `cost_coverage` counts executions. The Mac card uses
`Reported by X of Y executions` so each count reflects the contract,
including harnesses with a mix of reported and unavailable executions.

The Statistics overview shows Tasks run and Success rate beside
Reported cost. The design (`statistics/overview` at `be78fa43`) has a
four-card grid. The native overview adapts it to three cards: Tasks run,
Success rate and Reported cost. Agent time is deferred, as are Tasks per
day, By harness and a chain-aware Tasks ranking (the existing ranking
still lists each resume as its own row).

Definitions, from the owner decisions of 2026-11-22:

- Tasks run counts top-level standalone tasks. Child runs, retries and
  workflow runs are excluded, except that a task an agent started
  counts as top-level (see the limitations below). A task and its resumes and continuations
  are one chain, linked through `continuation_of_task_id` and
  `parent_task_id`. A chain is counted on the day its first run started,
  using the snapshot's calendar and anchor.
- Success rate is completed chains divided by counted chains. The
  outcome of a chain is that of its latest finished execution. Failed and
  timed-out chains count as failed. Cancelled chains are not successful
  and are not counted as failed. The percent is rounded half up and is
  never 100 while a chain did not complete or 0 while one did. With no
  eligible chain the card shows Unavailable and "No eligible finished
  tasks".
- Repository, harness and requested-model filters apply to the chain's
  first run. A member run with another harness keeps the chain whole and
  its outcome counts.
- An execution whose first run is absent from, or unreadable in, the
  available history is not counted and appears in a neutral coverage
  line. An invalid record is not counted and appears in a separate line.
  A record is invalid when its task id is missing or empty, its status
  is not a supported terminal status, its start or finish time is
  missing, its kind is unknown, workflow-only or disagrees with its
  links, or its task id is repeated among otherwise valid records. Every
  record of a chain with a link cycle or more than 1,000 hops is invalid,
  root included. Each excluded execution is counted once, invalid record
  first.
- When a repository, harness or model filter is active, the exclusion
  coverage lines count only excluded executions whose own repository,
  harness and model match, because their first run is not known.

Limitations, recorded honestly in the on-screen coverage lines:

- Tasks that an agent started count as top-level tasks, because the
  statistics page does not carry `spawned_by` or `root_task_id`.
- The outcome is as of the latest finished execution. A follow-up that
  is still running is not visible.
- Tasks still running without a finished execution are not shown.

Follow-up, not implemented: an additive statistics-page field
(`spawned_by` or `root_task_id` plus an active-successor flag), scoped
first in the canonical contract owner, then vendored and gated here.

Resource Slots Retry reuses the existing read-only refresh. A failed
refresh keeps the last successful observation, disclosure, viewport
and exact permission reason. An unavailable read and a stale retained
observation each offer Retry in context.

The over-capacity meter uses consuming inventory holders and the queue
for the exact named resource. It distinguishes filled used cells,
an outlined overflow cell and dashed waiting cells. Borrowed holders
consume no cell. Larger or conflicting observations keep the exact
text summary. The native disclosure retains its full accessible label
and the keyboard focus ring clears the meter.
