## Typed public behavior

`TaskPromptResult` is an Equatable/Sendable projection of the public result, preserving task identity/title, exact optional text, returned/total UTF-8 bytes, truncation, completeness, four availability states and four integrity states. It retains the raw additive result, including nested unknown fields and explicit `resolved_from {input,task_id}` provenance. Unknown keys are tolerated; unknown state/integrity values and malformed known types fail explicitly. No failure becomes an authoritative empty string or successful unavailable result.

Counts use strict integer tokens, not Boolean or floating-point substitutions. Returned bytes must equal actual text UTF-8 bytes and stay within the requested1...131072 limit (default65536). Complete text cannot be truncated and must match a known total. A verified sidecar may still be truncated/incomplete; an unverified prefix may have returned bytes greater than a race-observed source total, so that comparison is deliberately not imposed. The client does not trim/reformat whitespace, enforce an event-page document ceiling on JSON-escaped prompt text, access sidecars or verify private files itself.

`CtlClient.taskPrompt` uses the existing protected argv and typed ctl envelope/refusal path, with a fresh selected-runtime compatibility/capability handshake per operation. Missing `task-prompt.v1` prevents command launch. It accepts only the requested exact task identity or an explicitly proven matching prefix resolution; foreign/malformed resolution fails. Late cancellation/supersession rejects either a success or failure after the command. Structured public refusal data survives unchanged.

The one-shot `TaskPromptRepository` requires an explicit caller generation/lifetime fence, with no permissive default. Its implementation captures the selected client and composes the existing client fence, caller fence, cancellation and current local tooling identity (executable, effective environment, compatibility root/version). Checks occur before probe/command through the client gate and again after suspended results, before returning or reporting recovery. Current state-refusal errors may reach the existing narrow recovery surface; obsolete errors cannot. The caller owns selection ABA/request generation and must recheck before future presentation. There is no cache, timer, subscription, ToolEnvironment API expansion or new ambient runtime lookup. Module registers the adapter alongside existing bounded public readers; unconfigured reads fail explicitly.
