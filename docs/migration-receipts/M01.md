## Serialized change and isolation protocol — proposal

1. A single named MCP contract lead owns the pending delta queue until accepted O04; owner names the person/session before parallel implementation. Each delta states operation, authority, version/capability, bounds/cursor/generation, unknown/refusal semantics, fixtures/tests and affected consumers.
2. Serialize canonical spec/schema/fixture production. An accepted producer commit precedes adoption; record old/new manifests and changed capabilities. No concurrent consumer edits to canonical semantics. Engine mirrors the accepted public behavior until transfer, not a second contract owner.
3. Mac vendors exact complete fixture bytes and updates typed adapters/gates; Rust pins the same identity and supplies independent behavior/fault oracles. Each slice records pinned producer, consumer commit, adoption tests and unresolved cells. Changed behavior invalidates affected evidence only; do not repeat unchanged evidence or infer equivalent sources.
4. File ownership: Mac host/features/repositories/Swift fixture copy in HarflowMac; Rust crates/store/process/adapters/tests in HarflowEngine; canonical Python/spec/fixtures in HarflowMCP; approved specimens only in HarflowDesign. Tracker owns governing plans/AGENTS/ledger. No sibling-source build dependency. No cross-chat messages or shared uncommitted file ownership.
5. Future tests use unique per-invocation HOME/XDG/state/tmp/workspace/MCP registration names and credentials; Python and Rust never write one state root. No history import or live-process adoption. Keep provider credentials absent in deterministic fixtures. Isolated roots are not OS confinement.
6. Before any future shared resource use, allocate exclusive provider session/account, device/simulator, port, worktree/repository and service/slot capacity across roots. Separate roots do not coordinate resource slots. Use a recorded lease/allocation owner and refuse overlapping assignments; no real provider resource allocated by M01.
7. Serialize native guarded package tests, hosted UI/window focus and packaged startup. CI/build/signing changes stay Mac-owned. Credentials and install/registration/cutover/publication require their own authorization. Both accepted M12 and R14 precede I01; O04 is the sole explicit contract-owner transfer.
