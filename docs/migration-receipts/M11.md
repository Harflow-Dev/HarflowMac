# M11 — Settings, onboarding and runtime states

M11 is not started or accepted. This file records only the O-1 decision on the update-failed sidebar.

## Update failed

The design draws `harness-runtime/update-failed` (HarflowDesign `e1c9230`)
with a populated sidebar, on the reading that the installed runtime was kept
and its tasks stay listed. Under the 0.0.14 engine pin the populated sidebar
is empty: a session reaches the failed-update state only through an
update-required gate, so the runtime was never ready in that session, the
work listing was refused from the start, and the app persists no listing. The
sidebar therefore keeps its setup line while nothing has been listed, and the
main pane shows the design's failure gate with Retry setup (owner decision
O-1, option a2).

If a later engine pin, or an app-side cache, keeps listings across a failed
update, the "Show tasks, no actions" form applies (decision A4): the sidebar
shows the populated navigation and lists with creation and navigation
actions disabled, and no engine call is made while the update is failed. The
code path exists (`SidebarSetupGate.applies` shows the populated sidebar once
something has been listed, and `SidebarViewModel.creationIsAvailable` stays
false until the runtime is ready) and is covered by unit tests with fakes. It
has no hosted rendering and no copy beyond the gate's.
