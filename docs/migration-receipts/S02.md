## Public boundary and persistence coupling

Paths here are relative to HarflowMac. `macos/HfCore/MonitorCore/Sources/MonitorCore/`
contains the public adapters:

- `CtlClient.swift` checks version-info before commands, capability-gates dispatch,
  uses bounded argv and JSON, validates envelopes and lexical state-root binding.
  It covers list/status/status-batch/backends/run/resume/send/cancel-message/cancel/
  takeover. `HistoryPage.swift`, `StatisticsModels.swift`, `ResourceSlotsClient.swift`,
  `CtlClient+CallerApprovals.swift` (approval-list/get/respond), task/workflow
  artifact clients, `TaskRecovery.swift`, `InteractionEvents.swift`
  and `StateRecovery.swift` supply history, statistics, resources, recovery and
  interaction reads. Qualification extensions expose preview and explicit qualify.
- `WorkflowClient.swift` constructs dynamic `workflow-<command>` operations,
  including messaging/checkpoint capability checks. Repository/feature callers
  include build, builder-followup, cancel-message, delete, detail, get, inspect,
  list, preview, revise-goal, send, start and status. This is a source inventory,
  not complete execution coverage.
- `SetupClient.swift` uses status/install/remove with optional client and JSON.
  Independent gates remain ctl `[1]` in `CtlModels.swift`, setup `1` in
  `SetupClient.swift`, and events `1` in `Events.swift`.
- `HfRepository`'s `ManagedToolEnvironmentRepository.swift` uses the coordinator's
  qualified runtime/root; its `toolDirectory` argument is ignored. A retained
  legacy environment implementation is not evidence of production selection.
  Later note: that legacy implementation, `ToolEnvironmentRepositoryImpl`, was removed at the commit
  "Remove the legacy tool-environment repository" (2026-11-13).

The app is not exclusively coupled through process-level public operations:
`Titles.swift` reads up to 256 KiB from the first event-log line for task prompts;
`EventPages.swift` reads local bounded event pages with `FileHandle`; `Tail.swift`
uses a descriptor `DispatchSource` and `LineTail`. `EventStreamRepositoryImpl.swift`
constructs task event paths and folds their history/summary after compatibility
checks. `TaskList/DirectoryWatcher.swift` observes the tasks directory with
FSEvents (since-now, file events, 0.3 s latency). Compatibility logic starts it
after a successful initial refresh, filters `RefreshTrigger` filenames, throttles
and reconciles on safety timers (10 s, stretched to 30 s idle, 60 s unconditional).
Later note: the prompt reader in `Titles.swift`, `EventPages.swift` and `Tail.swift` were removed at the commit
"Remove unused engine-file readers from MonitorCore" (2026-11-13); `Titles.swift` itself remains.
No event-file writes were found in these paths. A browser-safe client needs public
activity/title/change observations; reproducing native file access is not parity.
