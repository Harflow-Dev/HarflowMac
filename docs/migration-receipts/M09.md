## Slice 3: selected-node pane

Baseline `0bda5c8370305e6df86bc5ed49948eb90eaa7867`. Design: HarflowDesign
`7de89a47137c261e5a1baaf4ef6504eb9e67a267`, `v2/scripts/screens-workflow-run.js`
`workflow-run/graph-needs-you` and `workflow-run/on-demand`, `v2/scripts/states-run-actions.js`
`workflow-run/node-message-unavailable`, `.hd-pane` in `v2/styles/bundle.css`.

Delivered:

- The selected-node pane's ideal width is 460 points (was 420); the clamp is unchanged.
- Worker and child-workflow nodes: a head with the node title and status badge (the canvas
  node's label for the latest attempt, the attempt's own status for an older attempt chosen in
  the attempt picker), then the run goal block and a `backend · model · repository` caption above
  the transcript. The goal and caption scroll as one region capped at half the pane.
- The node task's caller-approval panel sits inside the inspector column between the feed and
  the composer. It mounts under the run sidebar's condition (caller-approval opt-in or pending
  approvals), polls only while the run is running or needs input or attention, and targets the
  task of the conversation shown. Its region is capped and scrolls. Sizing reserves the measured
  pane head, picker, fallback composer, conversation picker and column chrome so the feed keeps
  an 80 point floor.
- On-demand nodes: the head reads `On demand`, then the intro line, a `CALLS` list of selectable
  rows (newest first, status glyph, `Call N · Status · mm:ss` with a row-local live clock for
  running calls, `Open task` when the call has a task), `Not called yet.` for a node never
  called, then the selected call's caption and transcript. When a call has no task or its
  activity cannot be shown, a compact block keeps its assignment, reason and result. The call
  history disclosure and `WorkflowOnDemandCallsView` are removed.
- `CallerApprovalPanel` restarts its polling task when `polls` changes, so a run that settles
  stops polling (applies to the run sidebar too).

Deviations from the drawn states:

- The worker pane keeps Close; it is the explicit keyboard and VoiceOver route back to the run
  summary (canvas background click also deselects).
- The attempt picker stays for workers with more than one attempt (not drawn).
- The single scrolling body is separate regions, because the transcript is a self-scrolling
  native feed.
- The inspector column's own title, subtitle and live status row is not drawn in worker and
  on-demand panes; the pane head and caption replace it. A non-latest fallback task's own status
  and the live elapsed time are therefore not shown there. The orchestrator keeps the row.
- An approval request on an earlier fallback task appears only when that conversation is chosen.

## Slice 4: goal block

Baseline `7010b99f`. Design: HarflowDesign `7de89a47137c261e5a1baaf4ef6504eb9e67a267`,
`v2/scripts/screens-workflow-run.js` `workflow-run/graph-needs-you` and `workflow-run/recovery`,
`v2/scripts/states-run-actions.js` (Goal). Status: implemented, hosted validation pending.

Delivered:

- The goal block is always expanded: label (`GOAL`, or `Goal · revision N` from revision 2), the goal
  text, an assessment row with the target symbol, a collapsed `Revision history` disclosure (earlier
  revisions only, newest first) and an accent `Revise goal…` link. It is mounted by the default run
  sidebar and by the selected-node pane.
- The revise form shows the current revision label, a four-line field, the shared-answering caption,
  `Cancel` and `Save goal`, and a failure alert that keeps the draft. A lost race replaces the block
  with a `Goal` card (the winning answer and the saved draft) until the run moves past the expected
  revision plus one. The screen header drops its copy of a goal-revision outcome while a goal block
  is visible.
- The draft, its editing session and the last save error live in the view model, so the default
  sidebar and the pane share one draft. A save applies its result only if the same run and editing
  session are still current; edits typed while saving are kept on the new revision.

Inferences and deviations (owner items):

- Assessment copy: only `in progress` (running) and `not met yet` (paused or needing input, no
  assessment yet) are drawn. `met`, terminal `not met` and `unverifiable` are undrawn.
- The assessment reason and evidence references stay visible as faint lines (undrawn).
- The answer excerpt label keeps the engine's truncation flag; the design labels it always.
- A revision race lost after the user cancelled (or switched run) is dropped on purpose: no receipt,
  saved draft or card is retained, and the caller's goal appears on the next refresh.
- `not met yet` for a paused or input-needing run without an assessment is an inference: the engine
  writes an assessment only at End.
