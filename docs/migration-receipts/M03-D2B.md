## Implemented boundary

- Both production activity and cumulative-summary file readers in `EventStreamRepositoryImpl` are replaced by the shared public page session. There is no private or MCP fallback. Unused lower-level legacy helpers are not claimed removed from the library.
- One atomic frame carries normalized records, strict semantic projection, history health, local session/source/window identity and independently qualified optional totals. Public sequence numbers remain record data; file-order admissions identify occurrences. Unknown/truncated/unsupported records survive as raw normalized evidence and break matching continuity.
- Activity admits whole pages up to 2000 records/4 MiB serialized bytes. Capacity retains rows and delivery cursor until explicit window replacement. Summary has independent bounded keys/calls, publishes at most 100 file entries and remains unavailable when its qualification is uncertain. These engineering bounds are not a measured heap or runtime-performance acceptance.
- One operation is active per session, with a global two-operation event budget. Each tick admits at most two forward activity and two summary-tail pages; a newest bootstrap is distinct from forward polling. Historical traversal/recovery has a cumulative 4096-operation ceiling. Overlapping older-page requests coalesce atomically through completion.
- Invalid cursors retain cached rows until explicit source adoption. Exhausted recovery has no inert adoption action. Runtime notifications fence activity, request and recovery work, then reacquire exact retained role interests. An activity role can suspend while a summary role preserves its bounded window; final role release clears the holder.
- Projection and normalized JSON preparation run outside the main actor. A latest-value mailbox admits only one pending Main delivery per holder, including while background replay progresses. Queued values recheck lifetime/currentness before consumers apply them.
- Stored assignment text uses the typed public reader only: initial 65536 bytes, one larger replacement up to 131072 per explicit request cycle, and same-bound retry after failure. Completeness, integrity, truncation and availability remain separate. Event display prompts are not assignment authority. Full-copy labels require complete untruncated verified or integrity-not-applicable text; partial/preview copy is qualified and integrity failure withholds text.
- Task detail uses the bounded transcript/request/Events arrangement. Existing snapshot facts, reported result, usage, artifacts and execution actions remain accessible. Current-turn recovered transcript is separate from the first-turn stored request. Parallel recovery has its own generation-labelled rows and contributes no captured counts.
- Visited Parallel reading windows remain cached across viewport suspension. A new scope or source reset requires explicit replacement, preserving the old anchor until consent. Capacity replacement keeps independently qualified summary facts. History cards are restricted to ordered active windows; bounded file entries have a disclosure rather than unsupported expansion.
