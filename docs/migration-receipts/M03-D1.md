## Contract and scope

Canonical producer remains immutable released0.0.8 `f304a65d9de948dfcba4c0c27c3d04f7f90971c8`; adopted full199-fixture bundle manifest is `6e742e1966d2b48afbfc80268b19f27da1e3f75f046f5683a35fc671228c7ce1`. This stage changes neither fixtures nor runtime pin0.0.7, and never imports/executes engine source, installs/selects a runtime or consumes the moving watcher draft.

D1 implements typed task-events pages/records and request enums, preserving raw additive facts, independent nested event provenance, normalization truncation/stubs, skipped scan windows, gaps, file-order span endpoints, opaque directional cursors and explicit lifecycle states. Native request limits fail explicitly rather than clamp or reinterpret. The query echo and exact task identity/proven prefix resolution are validated. Nonempty events or gaps require an accounting span; empty filtered pages can have spans, empty unaccounted pages may have none. Repeated/regressing sequences remain producer data in file order, not sorted/deduplicated globally.

The selected client performs one fresh ctl+events compatibility probe and named capability check per operation. Task-events alone gets the preparse262144byte document gate and post-probe/post-response cancellation/current-generation checks. Generic mutation outcome reporting is unchanged. Structured public refusals retain their data/reload instruction. Missing capability is unsupported, with no private/MCP fallback in the new client.

Normalized records are not original private JSONL bytes or untruncated text. The producer can truncate strings/lists/depth or return oversized stubs; the old parser would invent ok=true or empty text for missing fields. D1 intentionally exposes no automatic legacy TaskEvent projection. Full stored prompt authority remains the separate typed task-prompt contract. Final is lifecycle evidence, not complete history or proof an older page reached the forward frontier. Equal change tokens are not page/generation certificates.

The conservative per-record size meter uses an unescaped compact lower-bound profile so valid Unicode-expanded wire records are not rejected. The full stdout ceiling bounds JSON admitted to parsing; baseline process capture and native heap are not newly bounded by that check. Explicit-filter argv admission is200input names/16KiB UTF-8; cursor admission is2048Unicode scalars, no decoding. These native limits are distinct from producer scan/lifecycle guarantees.
