# Profiling

Runtime profiling is unavailable until the managed Harflow runtime is integrated. The profiler refuses execution with an explicit unavailable error before copying or launching an app or writing measurement output. It must not report an empty unavailable application as a populated fixture benchmark.

`python3 scripts/profile-monitor.py --help` remains available. The future profiling interface takes an explicit version-1 `harflow.monitor-fixture` manifest generated by the engine fixture exporter, with an isolated HOME and restricted control/setup wrappers. Fixture generation remains useful for the later runtime integration work.

Build locally with `macos/build-app.sh`. The build uses an ad-hoc signature and does not install, launch, or register the app. No runtime performance measurements are claimed for this stage.

## Start-screen retained history

The start screen reads complete retained primary task and workflow history independently
of sidebar pagination. Each source is capped at 100 pages, 10,000 received rows and a
cooperative 30-second deadline. Scan starts are separated by at least 30 monotonic
seconds, including retries and invalidated results. Definitions are loaded independently
within the same structured scan so workflow choices remain available while history reads
continue. There is no per-item detail fanout. Large retained histories can still require
many CLI processes within those caps; incomplete or over-budget reads show unavailable
metrics rather than totals from incomplete history.

## Window-root clocks and motion

Any `TimelineView` in the main window, including one inside a nested hosting view under a representable (sidebar rows, feed rows, the workflow viewport), makes the window's root `NSHostingView` re-measure on every tick: the pending update climbs through the platform hosts to the root, which re-runs its size and layout over the whole graph. A 30 Hz clock therefore costs about 60 root passes a second, and a closed window keeps paying it while its hierarchy is alive. The rules:

- Continuous motion runs in Core Animation, never in a `TimelineView` or a repeating SwiftUI animation. HfUI's shimmer (`HfShimmerLayerView`: a 1.4 s cosine sweep on a gradient layer, or under Reduce Motion a 1.6 s opacity pulse between 1.0 and 0.55 on a layer of the `skeletonFill` tone), the running spinner (`HfLayerSpinnerView`, which `StatusIcon`, `StatusBadge`, `TaskStatusBadge` and `LoadingLabel` all draw) and the running workflow node outline (`LayerOutlineView`, a conic gradient turning once every 3 s behind a ring mask) are layer animations phase-aligned to the reference date through `beginTime`. The shimmer's Reduce Motion choice stays `shimmerReduceMotionOverride ?? accessibilityReduceMotion`. A placeholder that is not a plain or rounded rectangle passes its outline to `shimmering(maskedBy:)`, because a layer-backed overlay cannot be relied on to follow a SwiftUI `.mask`.
- The 1 Hz and per-minute clocks in the window's root graph (`TaskStatusLabel`, `TaskLiveClock`, the Inspector and Summary clocks, the workflow call rows, `StatusPill`, `NeedsYouAgeText`) use `HfClockSchedule`, which yields no entries while `hfMotionPaused` is true and a fresh entry at the moment it resumes, so a clock shown again is current at once. `MainWindowCoordinator.motionPaused` follows `MonitorVisibility.mainWindowVisiblePublisher()` (after `receive(on: main)`, written only on change) while the shell observes, and `MainWindowNavigationView` injects it as `hfMotionPaused`.
- A flip of `motionPaused` re-evaluates the navigation view's body and re-runs `updateNSView` of the representables in the root graph (no-op diffs). That is accepted because visibility flips are rare.
- Accepted residual: the per-second clocks inside row hosts (`TaskRow` in sidebar rows, `ActivityFeedSupplementaryRow` in feed rows) are not paused. Delivering the flag through the rows' environment copies and fingerprints would make every visibility flip remeasure the sidebar and reconcile the feed. If that residual matters, deliver the flag only to the row hosts' root views without touching the fingerprints.

## Activity feed

Native activity rows retain text selection. The table owns displayed hosting views;
removing a native row releases its hosted content rather than keeping a SwiftUI graph
for every row visited. Reading anchors and group disclosure remain feed state.
Only explicit public presentation environment values cross into row hosts. The running
indicators inside feed cells (the streaming caret, the tool spinner, the working glyph and
the live-step pulse) animate in Core Animation through layer-backed views, never through a
SwiftUI `TimelineView` or repeating animation: a SwiftUI animation inside a hosted cell keeps
its graph pending every frame and makes the feed's host re-measure the whole table.
A row arriving while the feed follows live fades in the same way: a Core Animation opacity
animation (`HfMotion.arrivalDuration`, ease-out) on the cell's host layer, played once when the
cell first hosts the row. The coordinator keeps the ids added while following that have not yet
mounted; the next build made while the feed is not following clears them, and a row added while
the reader is above the tail never fades. The fade is not part of the native entry, so it never
forces a row to re-measure or refresh. Tool-group member fades inside a hosted card still use the
SwiftUI fade.
These layer indicators resolve their colours from the effective appearance of their AppKit view. That is the window's appearance, except where a SwiftUI colour-scheme override is set on the row: SwiftUI applies it to the hosted view as an appearance, so the override wins (measured for the caret, the tool spinner and the pulse dot). HfUI's shared `RunningSpinner` is also a Core Animation view (`HfLayerSpinnerView`) with the same look, and the feed's `FeedRunningSpinner` keeps its own `LayerSpinnerView` (same look and phase) because the feed's hosted tests inspect that type.

Unchanged feed inputs refresh action callbacks without rebuilding native entries or
remeasuring rows. Background presentation preparation supplies row revisions so native
reconciliation can distinguish changed content without deep-comparing message and tool
history on the main thread. Geometry and environment changes still invalidate the
affected measurements.

Changed snapshots still scan lightweight native entry IDs and measurement keys;
background preparation compares retained row payloads. The boundary removes deep
history comparison from native reconciliation, rather than making all update work
independent of loaded history size.

Hosted regressions cover unchanged-input work, visible host identity, environment
changes and scrolling retention. These checks do not reproduce the original long-session
18 GB peak or establish a full application memory ceiling; loaded history itself remains
retained. Production profiling remains subject to the runtime integration limitation above.

To include the two-minute synthetic 3,000-row streaming soak in the guarded suite:

```sh
HARFLOW_ACTIVITY_SOAK_SECONDS=120 HARFLOW_NATIVE_SIDEBAR_BENCHMARK=1 python3 scripts/test-swift-package.py --package macos/HfFeatures/MainWindowFeature --mode suites
```

The opt-in test reports process CPU, resident memory, physical footprint and native
host counts, and verifies that settled reconciliation and measurement work stops.
Without the duration variable, ordinary suite runs do not exercise the timed soak.

`ActivityFeedStreamingCPUProfileTests` attributes the soak's streaming CPU. It is opt-in in the same
way: each variant runs only when its own variable holds a duration of at least 60 seconds, and an
invalid value prints a skip line. Every variant changes the same 3,000 retained rows at the
soak's tick rate:

- `HARFLOW_ACTIVITY_CPU_FIXED_SECONDS`: the soak's tick, one fixed-id streaming row.
- `HARFLOW_ACTIVITY_CPU_NO_CARET_SECONDS`: the fixed row with the Reduce Motion override, which
  removes the streaming caret's blink animation (a layer animation) and leaves it static.
- `HARFLOW_ACTIVITY_CPU_PREBUILT_SECONDS`: the fixed row with every row array and snapshot prepared
  before streaming starts.
- `HARFLOW_ACTIVITY_CPU_APPEND_SECONDS`: each tick finalizes the streaming tail and appends a new
  streaming row.
- `HARFLOW_ACTIVITY_CPU_APPEND_NO_CARET_SECONDS`: the append stream with the caret's blink animation removed.
- `HARFLOW_ACTIVITY_CPU_ROOT_SIZING_OFF_SECONDS`: the fixed row with the test root hosting view's
  sizing options cleared.
- `HARFLOW_ACTIVITY_CPU_LIVE_TOOL_SECONDS`: no streaming text; a pending tool call with its running
  spinner ends the feed, and each tick rewrites the settled row above it.
- `HARFLOW_ACTIVITY_CPU_LIVE_STEP_SECONDS`: no streaming text; the standard style's live step line
  (the pulsing dot) sits under the feed, and each tick rewrites the last settled row.
- `HARFLOW_ACTIVITY_CPU_WORKING_ROW_SECONDS`: as the live step variant, in the transcript style,
  where the line is the working row with its turning glyph.

```sh
HARFLOW_ACTIVITY_CPU_FIXED_SECONDS=150 HARFLOW_NATIVE_SIDEBAR_BENCHMARK=1 python3 scripts/test-swift-package.py --package macos/HfFeatures/MainWindowFeature --mode suites
```

Set one variable per run so variants do not share a process. Each prints one
`HARFLOW_ACTIVITY_CPU` line with tick rate, CPU cores while streaming, with ticks stopped and after
the stream finishes (the running indicator is still shown while ticks are stopped, and removed when
the stream finishes), feed counter deltas and the native subtree size. CPU is `getrusage` for the
whole test process in a debug build, so the figures compare variants rather than give an absolute
feed cost.

## Parallel View prompt reads

Turning View prompt on starts one bounded stored-request read (64 KiB) per resident, leased lane, so a visible group issues as many concurrent reads as it has visible lanes (two to three at common window sizes). Each lane reads once per lease generation and only when its request was never read; toggling View prompt off and on, a second member's lease and scrolling a lane back in do not read again. Reads are cancelled with the lease or when the group disappears.
