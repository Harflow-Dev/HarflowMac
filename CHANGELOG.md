# Changelog

## Unreleased

## 0.1.0

- Indent nested Markdown list items in agent messages and summaries by 20 points per level (HarflowDesign `be5c743`, `.hd-msg-agent ul`), with disc, circle and square bullets by depth. Nesting follows the item's indentation (2 or 4 spaces, or tabs) up to four levels; ordered markers stay as written, and bullet glyphs are hidden from VoiceOver.

- Cut the idle CPU of the main window while something is loading or running, and while it is closed. The loading shimmer, the running spinner (in task rows, badges, lanes, the top bar and loading labels) and the running workflow node outline now animate in Core Animation instead of 30 Hz SwiftUI clocks that made the window re-measure itself every frame; their look, timing and Reduce Motion behaviour are unchanged, and the spinner still reads "Running" to VoiceOver unless its caller hides it. The running clocks and "ago" labels in the main window's own views stop while the window is hidden and show the current time again as soon as it is shown. Clocks inside sidebar and feed rows keep ticking while hidden. Under Reduce Motion a loading placeholder is now drawn by a pulsing layer of the same tone, clipped to the placeholder's rounded corners, instead of fading the SwiftUI shape, and a skeleton block under Reduce Motion looks the same on screen. Host bitmaps taken with `cacheDisplay`, including the review capture bitmaps, no longer show spinners or skeleton fills, because Core Animation layers are not rasterised there; the exact owned window captures still do.

- Show the notification permission in Settings → General (HarflowDesign `8ec4d38`, `settings/notifications-not-requested`, `-denied`, `-allowed`, `-unavailable`, menu bar and notifications record recommendation 3 and owner answer 7). After the two notify switches, a Notifications row says "macOS asks the first time Harflow sends a notification.", "Notifications are allowed for Harflow." or, when macOS has them off, "Notifications are off for Harflow in System Settings. The two switches above have no effect until you allow them." with an Open System Settings button that opens Harflow's notification pane; the two switches are disabled while they are off. A runtime without the interaction feed shows "This Harflow runtime can't send notifications. Update Harflow to use it." and disables the switches, and wins over a denied permission. The permission is read again whenever the app becomes active, and the row is absent when the app is not running from a bundle. "Open the window when a task starts" is never disabled.

- Remove a notification once its request is answered and open its Needs you item (HarflowDesign `8ec4d38`, `menu-bar-and-notifications.md` N1, click destinations and removal, owner answer 1). The "Answered in Harflow" and "Answered by the caller" notifications are no longer posted. Clicking a finished or failed task opens the task, and clicking an approval, question or recovery opens its Needs you item, or the Needs you list when the request is gone; banners delivered by earlier versions keep opening their run or task, and they are not removed when answered. - Add Tasks run and Success rate cards to Statistics beside Reported cost (HarflowDesign `be78fa43`, `statistics/overview`). Tasks run counts top-level standalone tasks that started in the selected period. A task and its resumes and continuations count once, by the day its first run started. Workflow runs, their nodes and runs whose first run is outside the period or unavailable are not counted. Success rate is completed tasks divided by counted tasks, using the outcome of each task's latest finished execution. A failed or timed-out task counts as failed, and a cancelled task counts as not successful without counting as failed. The rate is shown as a whole percent, never 100% while a counted task did not complete and never 0% while one did. With no eligible finished tasks the card shows Unavailable. Notes under the cards say that agent-started tasks count as top-level tasks, that tasks still running without a finished execution aren't shown, and how many executions were left out because their first run couldn't be identified or their record couldn't be read. Repository, harness and requested-model filters apply to each task's first run. The design's fourth card, Agent time, is not part of this change.
